# 后台开发 Agent 与日志筛选实施计划

**目标**　开发者从干净克隆开始，能让编程 Agent 按已有接口创建业务页、单独修改搜索条件。后台用户能用一句话生成可检查、可修改的操作日志筛选条件。

**实现方式**　开发指引随 Git 分发。运行时复用 `ProTable` 搜索表单和经过权限检查的日志列表接口。意图解析只接收提问和界面语言，输出模块、操作类型、状态三个枚举字段。静态 Demo 使用本地规则，服务端可接入 Ollama 结构化输出。

| 阶段 | 实施步骤 | 验收方式 |
| --- | --- | --- |
| 1 · 开发工作流 | 更新 `AGENTS.md`、`CLAUDE.md`、`README.md` 的入口及测试说明。在 `.agents/skills/antdv-next-admin/` 发布业务 Skill，精确放行其共享文件。给出从接口适配到页面、四种语言、权限和两套 Mock 的完整路径。 | 检查 Skill 格式和 Git 忽略规则，用现有用户页核对示例。复测 Issue #4 对应场景，独立搜索项可按自身顺序展示。 |
| 2 · 约束解析 | 在 `src/utils/logFilterIntent.ts` 定义与日志表单共用的字段枚举、输入和返回值校验、离线示例语法。在 `server/` 提供可注入鉴权和模型连接的解析器。开发 Mock 和静态 Demo 提供同一接口契约。 | 用 Vitest 验证四语示例、歧义和未知条件、非法模型返回、故障、未登录和缺少日志读取权限。检查发送给模型的内容。 |
| 3 · 操作日志页面 | 从操作日志表格打开筛选窗口，生成条件后先预览，确认后回填并展开搜索表单。用户仍可手改，再调用原有列表查询。更新通用分屏的演示标识和四语文案。 | 浏览器验证预览前后列表请求不变、填入值可见、搜索后返回的行和总数与筛选一致，同时检查取消和普通用户权限。 |
| 4 · 工程验收 | 运行定向和全量 Vitest、类型检查、lint、生产构建、构建产物检查以及 Playwright。检查改动清单与输出资源。 | 新功能从正常页面入口可达，Demo 和模型适配器共用相同输出约束。记录实测结果和需要真实环境完成的验证。 |
| 5 · 使用者验证 | 收集 5 位项目使用者最近的后台改动，用同一模型、任务描述、仓库版本，在有无 Skill 的独立副本各做一次，交替先后顺序。 | 由同一套功能断言比较首次验收通过率、人工返工分钟数、无关改动文件数。优先修复反复失败的任务。 |

### 回归任务

1. 给定分页接口及示例响应，新增一个管理页。检查查询参数映射、列表总数、空结果、只读角色、四语标签、开发与静态 Demo 行为。
2. 给已有列表增加一个仅用于搜索的字段。检查 `search.formItems` 的顺序、请求参数和原有列的顺序，用 Git 差异检查无关文件。
3. 登录有日志权限的账号，输入「找出用户管理模块里删除失败的操作」。检查预览的三个条件，回填后手改其中一个再搜索，核对表单、列表和总数。
4. 对无法表达的条件请求澄清，关闭窗口或切换页面后丢弃过期响应。验证无权用户在界面及只读 API 两处均受限。

### 后续能力的启用条件

试用期间记录需要写入的具体任务、影响范围和人工流程。重复出现同一写入需求后，围绕该任务设计草稿、受影响记录数、人工确认和审计，再评估实现。出现多个外部 Agent 复用同一受权查询的实际需求时，复用同一校验与鉴权实现提供 MCP 工具。
